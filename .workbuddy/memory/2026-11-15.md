## 超多方块结构系统改造为口木科技同款（未提交 / 未升版）

**用户两轮确认的口径**：
1. 改造对象 = 超多方块结构系统（`TTSuperMultiBlockMachine` + `SuperBlocks` + yml 字符矩阵），
   不是 3x3 `TTMultiBlockMachine`，也不是「大型结构填充棒」/「预制建筑」道具。
2. 兼容 = **保持现有 yml 与物品 ID 完全不变**，只换 Java 层实现，口木的好行为以兼容层引入。
3. 投影层 = **保留糖然分层投影**（六个 flag 全部照旧生效），只统一每格投影实体的生成方式。
4. 红色缺块提示触发 = **右键核心且未成形时**（不做填充棒触发、不做菜单按钮）。
5. 附加需求：排查「投影实体残留」（用户暂无稳定复现方式）。

**落地（5 个文件，零 yml / 零 ID 改动）**：
- 新增 `machines/superblock/SuperStructure.java`（199 行）：口木同款
  `StructureBlock(dx,dy,dz,Material,sfId)` 坐标表，注册期把 yml 字符矩阵**一次性编译**；
  提供 `cells(Dir)`（排除核心，供 SuperBlocks）、`checkStructure`（首错即返）、
  `collectMissing`（全量缺块绝对坐标）、`scanCells`、`isFormed`、`dirOf`。
  坐标公式逐字沿用旧 `buildInst`：`dx=c-coreOffset[2] / dy=coreOffset[0]-l / dz=r-coreOffset[1]`；
  旋转复用 `SuperBlocks.Dir.rx/rz` —— 与口木 `rot(x,z,dir)` 四向公式完全一致（已逐项核对）。
  比对仍走 `TTSuperMultiBlockMachine.matchesBlock`（粘液按 id、原版按材质、液体含 waterlogged），
  没照搬口木只比 `getType().name()`（会让 `a6: water` 永远判缺失）。
- 新增 `machines/superblock/TTStructureMissingHint.java`（411 行）：口木 `StructureMissingHint` 同款
  红色发光 ItemDisplay + TextDisplay 名称牌（客户端翻译 key）+ 聊天栏绝对坐标/前 12 条，
  `BlockPlaceEvent` 自动消失 + 粘液 id 延迟 3 tick 复查 + 3 秒聊天节流。
  **MAX_HINTS=48 上限**：口木结构几十格没设限，糖然 TR_HTY 有 535 格，照搬会一次生成 1000+ 实体。
  超限时按离核心距离取最近 48 处，聊天仍报总数并说明。
- `TTSuperMultiBlockMachine`：构造期编译坐标表并暴露 `structureModel()`；
  `isFormed/scanCells` 委托坐标表并读 `TTHorizonDirection` 做朝向旋转
  （**修掉旧版固定 NORTH、与 SuperBlocks 方向感知判定不一致的老问题**）；
  保留 `Cell(Block,Material,String,boolean)` 形状 → 大型结构填充棒零改动。
- `SuperBlocks`：`buildInst` 不再重复解析字符矩阵；`tryStart` 的朝向读取收口 `dirOf`；
  `createDisplay` 改口木同款 `world.spawn(Class, consumer)` + 统一实体属性；
  右键未成形核心调 `showMissing`；成形 / destroy 调 `clear`；
  未成形诊断日志用 `checkStructure` 给出首处缺失坐标（避免该方法成为死代码）。
- `TangranTechPlugin.onDisable`：调 `SuperBlocks.shutdown()`。

**投影实体残留排查结论（4 条路径，已全部加固）**：
1. **主因**：`createDisplay` 从未 `setPersistent(false)` —— Bukkit Display 默认 persistent=true，
   会随区块写进世界存档；重启后 `CORE / MONITOR / inst.projectiles` 三张内存表全空，
   旧投影无人认领也无人删 → 永久残留。且 `spawnProjectiles` 只在**未成形**时调用，
   结构已成形时连「按 PDC 收养」的路径都没有 → 残留实体永远进不了清理视野。
   → 现在 `applyCommonDisplayFlags` 统一 `setPersistent(false)`。
2. **启动清理**：`registerOnce` 延迟 20 tick 调 `sweepLegacyDisplays()`，只删
   「仍 persistent 且带 `DISPLAY_KEY`」的历史实体（本轮新建的已 persistent=false，不会误删）。
3. **重复生成**：`refreshCellSync` 原来在 `d == null` 时直接 `createDisplay`，
   插件 reload / 实例重建后 projectiles 为空但世界实体还在 → 叠出第二套。
   → 现在先 `findAdoptable` 收养，收养不到才新建。
4. **核心非破坏路径泄漏**：爆炸 / 活塞 / 其它插件移除核心不会走 Slimefun
   `BlockBreakHandler`，`CORE/MONITOR` 与投影一起泄漏。
   → `drainDirty` 每 600 tick 调 `sweepDeadCores()`：区块已加载且
   「id 明确变成别的方块」或「id 为空且材质也换了」才 `destroy`（避免缓存未命中误重建）。
5. **停服/reload**：`SuperBlocks.shutdown()` 清全部投影 + 内存索引 +
   `TTStructureMissingHint.shutdown()`（扫全服带 HINT_KEY 的 Display），主类 onDisable 调用。

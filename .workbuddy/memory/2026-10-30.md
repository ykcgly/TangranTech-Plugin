## v2.1.2 兼容层的严重回归：提前初始化 LogiTech 配方供应器（已按方案 B 修复，未提交）

**症状**：装上 v2.1.2 后，LogiTech 的逻辑快捷机器读不到其他附属的配方（静默缺失）。

**根因链（对方源码实证，LogiTech Build 3 / 51ee3a5）**：
- `RecipeSupporter.java:1889-1892` 静态块 → `initRecipeSupportor()` 干全部重活（扫全服配方）；
  `:43 public static void init() {}` 是空方法——它的唯一职能是「触发类初始化」，是个时序开关。
- 正常时序：`Schedules.java:36-41` 第 1 tick `runTaskLater(..,1)` → `PostSetupTasks.schedulePostRegister()`
  （:18-24 先置 `startPostRegister=true`，再调 `init()` 触发扫描）→ 此刻全体附属已注册，快照完整。
- v2.1.2 在 `onEnable` 里 `registerAll()` → `Class.forName(RS)`（默认 `initialize=true`）→
  **第 0 tick 就把扫描跑了**，晚于本插件 enable 的附属机器整批缺席；第 1 tick 的 `init()` 是空方法，
  `hasInit` 已置位 → **永久补不回来**。
- 连带：机器列表菜单（`AddGroups.java:637` 用 `MACHINE_RECIPELIST.keySet()` 快照，第 1 tick 构建）
  缺项；快捷机器 `getOrDefault`（`AddSlimefunItems:5296` 等）拿到空表。

**方案 B（用户敲定）**：
1. `LogiTechStackBridge.scheduleRegister(plugin)` 取代 onEnable 直调：第 2 tick 起轮询
   `PostSetupTasks.startPostRegister`（只读这一个 public boolean，该 clinit 只有一个 HashSet，不牵连
   RecipeSupporter），最多等 20 tick（字段名不一致时按时间兜底）；等到才 `registerAll()`。
2. 所有探测改用 `Class.forName(name, false, loader)`（不初始化）；`resolve()` 首行
   `if (!postRegisterDone()) return false;`（不写 probed，下次再探），彻底断掉提前初始化路径。
3. `buildRecipes` 前置 `ready()`（= available && postRegisterDone）；`getMachineRecipes()` 未装时
   探测一次即永久缓存空表。
4. `registerAll()` 的 `recipeList.put` 改「已存在则只计数不覆盖」——扫描期对方已存它自己转换后的形态
   （幂等性已核：`tryGenerateMGFromMachine` / `stackFromMachine` 对 MGeneratorRecipe / StackMachineRecipe
   都直接返回自身），覆盖会把我们的 carrier 塞回去。
5. 日志加「其中 N 台由对方扫描自动收编」，可据此判断时序是否生效。

**实际运行 jar 校验（javap 对 `plugins/LogiTech-Build 3 (git 51ee3a5).jar`）**：
`PostSetupTasks.startPostRegister`（public static boolean）、`RecipeSupporter.MACHINE_RECIPELIST /
STACKMACHINE_LIST / STACKMGENERATOR_LIST / transferRSCRecipes`、`MGeneratorRecipe(int,ItemStack[],ItemStack[])`、
`MachineRecipeUtils.stackFromMachine / tryGenerateMGFromMachine`、`StackMachine/StackMGenerator` 的
`BW_LIST / BW_LIST_ENERGYCOMSUME / BWSIZE / hasInit` 全部存在且签名一致。

**铁律补充**：跨插件反射对接，`Class.forName` 一律带 `initialize=false` 做存在性探测；
对方若把重活放在静态块里，"首次 touch 的时机"就是它的公开契约，抢跑 = 静默数据缺失。
